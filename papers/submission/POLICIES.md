# Submission policies for Wave 2

**Reviewed 2026-11-25.** Public policy pages were consulted without signing in. The [Wave 2 contract](../WAVE2-CONTRACT.md) records that models proposed conjectures and strategies, wrote proofs and prose, implemented Lean formalizations and computations, searched the literature and reviewed drafts. The owner directed the project and is responsible for release. Where a venue asks about author contributions, describe what each person actually did. Carry the contract's disclosure into the PDF and supply the venue's additional fields. Use the verification map to identify the declarations checked by Lean and the arguments that still need human specialist review. Cross-model review is not peer review.

## alphaXiv AI Track

**Eligibility.** The policy directs that “Papers that are mostly AI generated belong on the AI Track.” It welcomes fully AI-written academic papers and work in which AI ran the experiments. The owner needs an alphaXiv account, authority to publish and consent from any coauthors. The submitter attests to originality, absence of plagiarism and fabrication, and accurate title, authors and other metadata. The public policy specifies no subject endorsement or institutional-affiliation gate. It encourages checking the AI's results. The documented programmatic route explicitly accepts an empty author list when there are no human authors. Where the owner has an authorship claim, use the accurate owner-approved byline. Where the owner is solely the project director and release contact, confirm how the website represents that role and an empty byline before using the website. Record AI models in the disclosure. [Submission policy](https://www.alphaxiv.org/docs/submission-policy) and [MCP publishing documentation](https://www.alphaxiv.org/docs/mcp) (both accessed 2026-11-25).

**Files and metadata.** Prepare a compiled, searchable PDF. The documented publishing route takes a PDF up to 50 MB and extracts title, abstract and authors unless supplied explicitly. The documented route processes one publication at a time per account. Review each field and the byline order. For a first version the API also offers a URL slug. The public documentation establishes PDF intake and does not establish direct TeX source or source-archive intake. Link the version-pinned LaTeX source, Lean evidence and verification map from the PDF and landing page. Prepare Mathematics / Number Theory (`math.NT`) as the proposed subject and use other subjects only if justified. alphaXiv documents arXiv-style categories as paper metadata, but its publishing API schema has no category parameter and its public AI Track page does not establish the current signed-in category picker. Confirm categories in the signed-in form. Keep MSC2020 codes, keywords and evidence links in the PDF and submission pack. Dedicated form fields for these were unverified. [MCP publishing and metadata documentation](https://www.alphaxiv.org/docs/mcp), [AI Track](https://www.alphaxiv.org/ai-track) and [arXiv category taxonomy](https://arxiv.org/category_taxonomy) (all accessed 2026-11-25).

**Required structured disclosure.** The documented publish operation requires `ai_disclosure`. Rate each of idea, literature, experiments, analysis and writing as `ai`, `mixed` or `human`. Supply up to ten tool records, each with model, harness (null for plain chat or API) and contribution. The list can be empty only if every stage is human. Determine ratings per manuscript from the actual record, including which computations were run and who interpreted them. Owner direction alone does not establish mixed authorship of a proof. Confirm how the website handles a stage that was inapplicable and how it records multiple models. The contract's prose remains in the PDF. [MCP publishing documentation](https://www.alphaxiv.org/docs/mcp) (accessed 2026-11-25).

**Screening, duplicates and revisions.** “Screening is not peer review.” All submissions are screened for fit. Duplicate records (including reuploads of arXiv papers already indexed there), spam, impersonation, abusive content and nonacademic submissions can be rejected. The paper may be taken down for policy or rights issues. For substantive revisions, the original submitter uploads a new PDF against the existing paper ID or URL, using `new_version_of` in the documented API. The paper keeps its URL and prior versions remain accessible. Corrections to fields such as title, authors and categories do not create new versions. Withdrawal is by request and retains a record. Check whether B's earlier release already has an alphaXiv record. Use its revision route if directly hosted and controlled by the owner. If it is an imported record or cannot be updated by the owner, clarify the route with alphaXiv before filing a separate entry. With no existing alphaXiv record, B can be a first platform version while retaining manuscript v2.0 and its link to the earlier GitHub release. [Submission policy](https://www.alphaxiv.org/docs/submission-policy) and [MCP revision parameters](https://www.alphaxiv.org/docs/mcp) (both accessed 2026-11-25).

**Licence.** Publishing grants alphaXiv a nonexclusive, perpetual and irrevocable hosting, distribution and preservation licence. The optional public licences are CC BY 4.0, CC BY-SA 4.0, CC BY-NC-SA 4.0, CC BY-NC-ND 4.0 and CC0 1.0. An optional licence is irrevocable for that version. A later version may use a different licence. Confirm rights in the manuscript and third-party material before accepting the grant. [Submission policy](https://www.alphaxiv.org/docs/submission-policy) (accessed 2026-11-25).

## arXiv

**AI and moderation.** The published rule says “generative AI language tools should not be listed as an author”. Authors report significant use consistently with disciplinary methods and take individual responsibility for all contents, including AI-generated proofs, errors and references. arXiv evaluates scholarly standards, originality, substance and relevance and can decline work needing significant revision. A, B and C could fit the content type and subject of original `math.NT` research articles if the final papers establish the claimed results and an accountable human author can substantiate the proofs, citations, novelty and disclosures. The drafts and cross-model checks alone do not establish that readiness. arXiv currently limits each author to two new submissions per calendar month and three active submissions, with a one-per-week replacement limit after v5. A revision of B already on arXiv would use the existing identifier, while a prior GitHub release alone does not create an arXiv identifier. [Content moderation](https://info.arxiv.org/help/moderation/index.html), [content types](https://info.arxiv.org/help/policies/content-types.html) and [replacements](https://info.arxiv.org/help/replace.html) (all accessed 2026-11-25).

**Endorsement.** “arXiv requires that users be endorsed before submitting their first paper to arXiv or a new category.” For first submission in the domain covering `math.NT`, the January 2026 rules require both a qualifying institutional email and previous authorship of an accepted paper in the same endorsement domain for the automatic path. The account should claim the prior paper. Otherwise, start a submission in the intended category and use the resulting request link to seek a positive personal endorsement from an eligible active arXiv author in the domain. Use the endorser lookup attached to relevant abstracts. One positive endorsement is required per applicable endorsement category. Endorsement is not peer review. [Endorsement help](https://info.arxiv.org/help/endorsement.html) and [January 2026 policy update](https://blog.arxiv.org/2026/01/21/attention-authors-updated-endorsement-policy/) (both accessed 2026-11-25).

**Reviews and position papers.** The announced CS practice says authors of those papers “must include documentation of successful peer review to receive full consideration.” They must first obtain acceptance and successful refereeing at a journal or conference and supply the journal or conference reference and DOI metadata. arXiv's general list does not treat these as ordinarily accepted content types. The extra CS practice concerns surveys and position papers, so it does not apply to these three planned original number-theory research articles. [CS moderation announcement](https://blog.arxiv.org/2025/10/31/attention-authors-updated-practice-for-review-articles-and-position-papers-in-arxiv-cs-category/) and [content types](https://info.arxiv.org/help/policies/content-types.html) (both accessed 2026-11-25).

**Format and licence.** Package the LaTeX source and dependencies for arXiv compilation. Available licences are arXiv's perpetual nonexclusive distribution licence, CC BY 4.0, CC BY-SA 4.0, CC BY-NC-SA 4.0, CC BY-NC-ND 4.0 and CC0 1.0. “The license chosen is irrevocable and cannot be changed.” Different versions may use different licences. Confirm the owner's authority and any journal or funder licence requirements before choosing. [Submission overview](https://info.arxiv.org/help/submit/index.html), [TeX requirements](https://info.arxiv.org/help/submit_tex.html) and [licences](https://info.arxiv.org/help/license/index.html) (all accessed 2026-11-25).

## Journals and authorship

- **Acta Arithmetica.** “The principal mathematical ideas, results, arguments, and proofs presented in a paper must originate with the authors.” The journal generally limits AI to nonresearch tasks and checking author-developed arguments, requires independent verification by the authors and full disclosure of substantial use, and may reject AI-generated work without adequate human contribution, verification and responsibility. It permits prior preprints. The Wave 2 disclosure describes an origin of the mathematical work that conflicts with this journal's rule. [Information for authors](https://www.impan.pl/en/publishing-house/journals-and-series/acta-arithmetica) (accessed 2026-11-25).
- **Journal of Number Theory.** Elsevier's current policy states “AI tools should always be applied with human oversight and control.” It permits support such as generating ideas and synthesizing literature. Authors must verify the output and thoroughly revise it so the contribution reflects their own analysis, interpretation, insights and ideas. Use a named declaration before the references for manuscript preparation and document research uses in Methods or its mathematical equivalent. AI cannot be an author. The current drafts do not establish the required human intellectual contribution. This assessment uses the publisher policy and official journal scope. The journal-specific ScienceDirect guide could not be inspected in this review. [Elsevier generative AI policy](https://www.elsevier.com/about/policies-and-standards/generative-ai-policies-for-journals) and [journal scope](https://shop.elsevier.com/journals/journal-of-number-theory/0022-314X) (both accessed 2026-11-25).
- **Uniform Distribution Theory.** The Engineering Journals page under the expanded title *Uniform Distribution Theory: Mathematics, Computational and Engineering Applications* says generative tools “must not be used to create the scientific content of a manuscript.” It permits limited language editing, data-analysis assistance or stimulus generation and asks for a dedicated disclosure for permitted generative uses. A and C are topical, but the drafts conflict with that rule. The historical Slovak Academy journal also has a separate archive and publisher listing. Confirm the exact editorial office and current submission status before applying any policy to the historical title. [Engineering Journals author guidelines](https://engineering-journals.org/journals/udt/), [Slovak Academy listing](https://www.sav.sk/?doc=journal-list&lang=en) and [historical publisher listing](https://reference-global.com/journal/UDT) (all accessed 2026-11-25).
- **Combinatorics and Number Theory**, formerly *Moscow Journal of Combinatorics and Number Theory*. The journal's instructions point to MSP's draft policy dated 2026-11-01. It says “Authors must acknowledge any use of AI beyond routine help with language”. It requires identifying the results, proofs, computations and passages materially shaped by AI and makes authors responsible for correctness and claims about prior work. The journal requires original research and significant contribution from all named authors. This is a possible editorial inquiry after establishing accountable human authorship and preparing a result-level disclosure. The broad contract paragraph alone gives less detail than the policy asks for. [MSP journal list](https://msp.org/publications/journals/), [journal author policies](https://msp.org/cnt/about/journal/policies.html), [journal instructions](https://msp.org/cnt/about/journal/submissions.html) and [MSP draft AI policy](https://msp.org/publications/ai/) (all accessed 2026-11-25).
- **Integers.** “The narrative and all the wording in the paper must be those of the authors, and not be AI-generated.” The journal excepts spelling and grammar checkers, requires disclosure of other uses at the end of the manuscript and requires compliance confirmation in the submission email. The Wave 2 wording fails the rule as drafted, even where a result is within its combinatorial number-theory scope. [Integers submission instructions](https://math.colgate.edu/~integers/submit.html) (accessed 2026-11-25).
- **Experimental Mathematics.** Taylor & Francis states it “does not allow generative AI to create a first draft of a manuscript or sections of a manuscript.” Its current author guidance permits reviewed coding assistance and some editorial uses, requires a declaration about whether and how generative AI was used, and bars AI authorship. The manuscript drafting described in the contract is incompatible with that guidance. [Journal home](https://www.tandfonline.com/journals/uexm20) and [Taylor & Francis author AI guidance](https://authorservices.taylorandfrancis.com/editorial-policies/using-ai-in-your-research-and-manuscript-preparations/) (both accessed 2026-11-25).

**COPE and ICMJE-style criteria.** COPE states that “AI tools cannot be listed as an author of a paper.” Its position calls for disclosure of which tools were used and how, and assigns responsibility to the authors. ICMJE is a medical-journal standard and a useful model for judging authorship. ICMJE recommends that authorship be based on ?all four criteria?. These are substantial contribution to conception, design, acquisition, analysis or interpretation, drafting or critical intellectual review, final approval, and accountability. Its AI guidance calls for disclosure in the cover letter and manuscript, human review and editing, and excludes AI tools as authors. Project ownership and final release approval alone do not satisfy all four criteria. Credit other contributions accurately and record tool contributions in the disclosure. [COPE position](https://doi.org/10.24318/cCVRZBms), [ICMJE authorship criteria](https://www.icmje.org/recommendations/browse/roles-and-responsibilities/defining-the-role-of-authors-and-contributors.html) and [ICMJE AI use by authors](https://www.icmje.org/recommendations/browse/artificial-intelligence/ai-use-by-authors.html) (all accessed 2026-11-25).

## VibeMathed

VibeMathed is a curated catalog of mathematical problems solved wholly or partly with substantive AI involvement. The curator checklist says “Someone posed it before this work”. Document the exact earlier statement with the poser, date, stable primary link and problem number, page, section or pinned lines. A named conjecture, numbered problem, question in a paper or a tracked bound can provide that antecedent. Give a second primary source for the solution and show how its hypotheses and conclusion match the posed problem. The AI contribution must be disclosed in that source. Related prior art, a new example and a theorem that improves a result without answering a stated question do not establish an antecedent. [Methodology](https://vibemathed.com/methodology) and [curator checklist](https://github.com/mrconter1/vibemathed/blob/main/docs/reviewing.md) (both accessed 2026-11-25).

Submitters sign in and are credited by pseudonym after curation. Entries record the statement, dated proof source, result and status, AI role, verification and supporting links. A documented advance on a stated question can be marked Partial. Routine formalization of known human results, heuristics and empirical evidence alone are outside scope. VibeMathed distinguishes Lean-checked artifacts from its stronger Lean-verified tier, which additionally needs independent anchoring or an audit of statement fidelity and machine checking. Review or candidate labels should reflect what was actually checked. Curation and cross-model review are not peer review. [Submission form](https://vibemathed.com/submit) and [methodology](https://vibemathed.com/methodology) (both accessed 2026-11-25).

- **A, Disjunctive but Nonnormal Multiplicative Lambert Series.** The roadmap identifies nearby prior work but supplies no earlier posed question matching the announced family and discrepancy estimate. Hold unless the ledger identifies a matching antecedent and establishes what it answers. [Roadmap](../../docs/publication-roadmap.md).
- **B, Polynomial Images of Stoneham Numbers.** One conditional catalog candidate is the all-degree least orbit-order identity and its minimizing configurations. The earlier note poses it in §B.4, conjecture B.7 and open boundary 3. The later note proves it as Theorem 1, with a larger Kraft-bound extension in Theorem 3. The pinned commits establish the repository chronology, with both commits dated 2026-11-25. Verify the earlier formulation's public provenance and ask whether the curators accept this project-posed problem and the proof as an entry. Present it as an exact combinatorial question with a paper proof, without claiming a celebrated open problem or registering the entire manuscript. The broader all-degree dyadic Stoneham normality and the resonant quadratic question remain open in the source note. [Pinned antecedent](https://github.com/eldernos/MathematicsResearch/blob/dd8545ba8a7c8f764c07a72be974418f7befe157/notes/phase16/dyadic-stoneham.md#L286), [pinned resolution](https://github.com/eldernos/MathematicsResearch/blob/17e57702e4cbd6b66a9157636b30ab3802116a4b/notes/phase17/dyadic-stoneham-classification.md#L11) and [readiness notes](../../notes/phase17/dyadic-stoneham-classification.md).
- **C, Synthetic Arithmetic Expansions and Prescribed Discrepancy.** The assessment gives related constructions and the motivation for the project's question. It does not document an earlier posed problem matching the prescribed-discrepancy theorem. Hold unless the ledger supplies a dated statement and substantiates a resolution or a precise partial advance. [Publication assessment](../../notes/phase18/publication.md) and [source comparison](../../notes/phase18/sources.md).

## Zenodo

“All content on Zenodo must be grounded in research work conducted by its authors.” Zenodo excludes content largely produced by generative AI without a verifiable connection to legitimate human-conducted research. Substantive AI use belongs in the record description, including the tools, purposes and affected material across text, code, data and other outputs. The depositor and creators take responsibility for the record, and AI tools cannot be named as creators or contributors. Depositors need rights to share their material. Zenodo hosts research outputs without attesting to the correctness of the mathematics. The human research requirement applies to software and data as well as PDFs. [Generative AI policy for depositors](https://support.zenodo.org/help/en-gb/13-policies/227), [unsuitable content](https://support.zenodo.org/help/en-gb/2-content/141-what-content-is-not-suitable-for-zenodo) and [terms of use](https://about.zenodo.org/terms/) (all accessed 2026-11-25).

A Lean kernel check shows a derivation of a formal statement from specified assumptions. It supplies no evidence by itself about who conducted the research or how the formal statement corresponds to the manuscript. The disclosure assigns substantial intellectual work to AI, and the public rules do not resolve whether the owner's documented project direction and any separately evidenced human research suffice. Ask Zenodo before depositing an article or enabling a GitHub release archive. Provide the actual human contribution record, a pinned version, its verification map and the proposed record type. [Generative AI policy for depositors](https://support.zenodo.org/help/en-gb/13-policies/227) and [Zenodo support](https://support.zenodo.org/help/en-gb/) (both accessed 2026-11-25).

## GitHub Pages and scholarly metadata

- **Per-paper landing page.** GitHub Pages can host a stable public HTML page for each manuscript with its full visible abstract, clearly labelled preprint and version, PDF, source and evidence links. Provide crawlable links from the paper index, allow anonymous access and ensure the PDF has searchable text and stays within Scholar?s 5 MB file limit. Serve one paper per PDF. Keep versioned files and links for citations. [GitHub Pages documentation](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages) and [Google Scholar inclusion guidelines](https://scholar.google.com/intl/en/scholar/inclusion.html) (both accessed 2026-11-25).
- **Highwire Press metadata.** In each page's HTML head use `citation_title`, one `citation_author` tag per actual author, `citation_publication_date` with the citable release date in year/month/day format when known, and `citation_pdf_url` with an absolute, publicly reachable PDF URL within the paper landing page's directory. Keep metadata consistent with the PDF. Add a real DOI if assigned. Scholar says “At least one author tag is required for inclusion in Google Scholar.” An intentionally authorless paper fails that stated requirement. Scholar also asks for a visible full author-written abstract. The page provides no clear interpretation of solely AI-drafted abstracts in this case. Verify the actual served HTML and paths. Indexing cannot be promised. [Google Scholar inclusion guidelines](https://scholar.google.com/intl/en/scholar/inclusion.html) (accessed 2026-11-25).
- **Repository citation.** Put YAML `CITATION.cff` at the repository root. Use the CFF schema's `cff-version`, `message`, `title` and `authors`, with verified names, identifiers, version, release date, licence and repository URL as appropriate. GitHub exposes the citation from the default branch. A `preferred-citation` can point to a specific work if the owner approves. Maintain individual paper citations and version URLs on their landing pages. [GitHub citation file documentation](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-citation-files) and [CFF schema guide](https://github.com/citation-file-format/citation-file-format/blob/main/schema-guide.md) (both accessed 2026-11-25).
- **Zenodo release metadata.** If Zenodo confirms the release is in scope, a repository-root `.zenodo.json` can supply metadata for the GitHub archive, including `creators`, `title`, `description`, `upload_type`, `license`, `keywords` and `related_identifiers` where appropriate. Include substantive AI disclosure in the description. When both files are present, Zenodo uses `.zenodo.json` alone for the GitHub archive, while GitHub still displays the CFF citation. Verify consistency and preview the imported metadata before relying on it. A software release identifier and a manuscript identifier refer to different objects. [Zenodo JSON conventions](https://help.zenodo.org/docs/github/describe-software/zenodo-json/) and [Zenodo CFF conventions](https://help.zenodo.org/docs/github/describe-software/citation-file/) (both accessed 2026-11-25).

4. Ask Zenodo about the manuscripts and any proposed GitHub archive before depositing. Consider VibeMathed only for a documented problem-level result.
