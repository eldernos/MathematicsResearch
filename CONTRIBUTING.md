# Contributing

Mathematical review is the most valuable contribution to this repository. If you find an error, a gap between a formal statement and its prose, an earlier source for a result, or an unclear proof, please open a [GitHub issue](https://github.com/eldernos/MathematicsResearch/issues/new/choose).

## Reporting a correction or a reference

1. Identify the result by its identifier, such as ST-01 or LS-01, from the [curated result index](docs/results.md). If the issue concerns a lemma, give its fully qualified Lean name from the [declaration directory](docs/theorems.md).
2. Say which artifact is affected: the statement in the README or index, the written proof in `notes/`, a manuscript in `papers/`, or the Lean declaration.
3. For a literature reference, give the bibliographic details and the specific theorem, with its hypotheses if they differ.
4. For a suspected mathematical error, point to the step and, if possible, a counterexample or a missing hypothesis.

The [correction template](.github/ISSUE_TEMPLATE/correction.md) asks for exactly this. Reports are recorded and answered in the issue; resolved corrections are linked from the affected result.

## Changing the repository

- Lean proofs must build with `scripts/verify.sh`: no `sorry`, no new axioms, and audited theorems listed in `Audit.lean`.
- After changing Lean statements, regenerate the declaration directory with `NORMALITY_UPDATE_THEOREM_INDEX=1 lake env lean scripts/readme_theorems.lean`.
- Result statements live in `docs/registry/*.toml` (format in [docs/registry/SCHEMA.md](docs/registry/SCHEMA.md)); run `python3 scripts/portal.py build` after editing them. Identifiers are permanent and never reused.
- Follow the notation rules in [AGENTS.md](AGENTS.md) for anything rendered on GitHub.
- Figures are generated by `scripts/figures/`; edit the generator, not the SVG.

See [docs/verification.md](docs/verification.md) for the full set of checks.
